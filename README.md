# Aditya-L1 Solar Flare Forecasting (SoLEXS + HEL1OS)

Automated ML pipeline that **forecasts solar flares** from combined SoLEXS
(soft X-ray) and HEL1OS (hard X-ray) time-series data from ISRO's Aditya-L1
mission at Lagrange point L1.

## Results (holdout, 60-min-ahead forecast)

| Metric | Value |
|---|---|
| ROC-AUC | 0.914 |
| PR-AUC  | 0.314 (baseline positive rate 1.6% -> ~20x skill) |
| TSS     | 0.563 |
| HSS     | 0.399 |

## How it works

```
data/solexs/*.pi       data/hel1os/*lightcurve_*.fits
        |                          |
        +-------> data_loader.py <--+     builds 1-second grid, caches data/master.parquet
                         |
              src/features.py            rolling windows (1-60 min), gradients, bg-normalized
                         |
              src/flares.py              flare onset detection (adaptive threshold on SoLEXS)
                         |               + forecast labels: onset within [t+gap, t+gap+horizon]
                         v
              src/train.py               GradientBoosting + StandardScaler, time-ordered split
                         |
              src/predict.py             live nowcast/forecast scoring
              src/visualize.py           timeline + PR/ROC plots -> output/
```

**Label definition (avoids circular nowcast):** a sample at time `t` is
positive if a flare *onset* falls in `(t+GAP, t+GAP+HORIZON]`. With
`GAP=3600s`, the model must predict 1-2 hours ahead from quiet pre-flare
data — it cannot just detect a rise already in progress. Samples during an
ongoing flare are excluded from training.

## Demo web app (for pitching)

```bash
streamlit run app.py
```

Opens at http://localhost:8501 with two tabs:

1. **Demo mode (real data)** — drag a slider over the 20 days of real
   Aditya-L1 data; the app re-computes the forecast "as if now" and shows the
   flare probability, alert status and live light curves.
2. **Upload your readings** — drop in a CSV/XLSX of new SoLEXS/HEL1OS readings
   (a `time` column + channel columns); the app scores the latest timestamp.
   Column names are fuzzy-matched (e.g. `solexs_sdd2_counts`,
   `hel1os_czt2_40-60keV`); missing channels are filled with training medians.

Ready-made demo files (generated by `python make_samples.py`):

- `output/sample_readings_quiet.csv` — quiet window -> predicts ~6% (no alert)
- `output/sample_readings_preflare.csv` — ends 90 min before the 2026-07-22
  06:32 flare -> predicts ~66% (FLARE ALERT)

## Getting started

```bash
pip install -r requirements.txt

# 1. (already done) put raw zips under data/ and run once:
python extract_data.py        # unzips SoLEXS .pi + HEL1OS lightcurves
python -m src.data_loader     # builds master.parquet (1s grid, 21 channels)

# 2. train + evaluate
python -m src.train

# 3. forecast the latest data
python -m src.predict

# 4. plots
python -m src.visualize

# 5. demo app
streamlit run app.py
```

## Configuration (`src/config.py`)

- `HORIZON_S` / `GAP_S` — forecast window and minimum lead time (default 1 h / 1 h)
- `FLARE_MIN_PEAK`, `FLARE_MULT` — flare detection sensitivity on SoLEXS counts
- `CADENCE_S`, `SAMPLE_EVERY_S`, `LOOKBACK_WINDOWS_S` — feature grid & sampling
- `TRAIN_FRACTION`, `WASHOUT_S` — time-ordered split with leak-free boundary

## Data notes (issues found)

- SoLEXS `.lc` light-curve files are all-NaN in this release; valid counts live
  in the `.pi` spectra (summed over 340 channels). SDD1 has empty GTI (no data).
- HEL1OS light curves use MJD; rounded to whole seconds to align channels.
- ~21 flare events detected over 2026-07-18..08-06; both instruments agree on peak times.
